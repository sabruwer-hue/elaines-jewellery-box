## Changes made during this audit
1. **Fixed public-intake validation ordering.** The handler previously required both a valid email address and a two-character name before checking the request type. This incorrectly blocked newsletter sign-ups with an optional blank name, unsubscribe requests that only carry a token, and the authenticated admin new-stock campaign action. Contact details are now required only for Studio enquiries, customer-care cases and reviews; the newsletter handler validates its own email and consent.
   - Source: `supabase/functions/public-intake/index.ts`
   - Deployed to Supabase as **public-intake v12**.
   - Verified the deployed function is ACTIVE and contains the new validation.
   - Full browser/API submission testing remains outstanding.
2. **Expanded the XML sitemap** to include the public Creation Archive, Privacy Policy and Terms pages as well as the homepage. The admin page remains excluded.
   - Source: `sitemap.xml`
3. **Added three missing foreign-key indexes** identified by Supabase's performance advisor:
   - `admin_push_subscriptions(user_id)`
   - `customer_new_arrival_campaigns(product_id)`
   - `studio_quotes(created_by)`
   - Applied as migration `add_missing_foreign_key_indexes`.
   - Verified all three foreign-key columns now have covering indexes.

## Security and performance findings
- **Security warning remains:** Supabase Auth leaked-password protection is disabled. Enable it in the Supabase Auth password-security settings. This requires a dashboard-level Auth configuration change and was not changed by this audit.
- Supabase performance advisor reports multiple permissive RLS policies on 11 tables. These are performance warnings, not proof of an access-control bypass; review policy overlap and consolidate only after validating the intended public/customer/staff access matrix.
- The advisor also reports 53 unused indexes. Do not mass-delete them: this is a relatively new project and low usage can make valid indexes appear unused. Reassess after real workloads.
- No claim is made that every RLS policy, Storage bucket or customer-data path has passed a full penetration/security test.

The public site and admin code may be deployed, but this audit does not certify that the custom domain is currently reachable or that every GitHub Actions deployment/APK build triggered by recent commits has completed successfully.


## Additional audit — custom-order commerce, payments and future Career Guide
A deeper architecture review was completed on 11 November 2026 and recorded in `CUSTOM_ORDER_COMMERCE_CAREER_GUIDE_COSMO_AUDIT.md`.

### Confirmed existing foundations
- Orders, order items, payments, invoices, product catalogue, historical archive, creation enquiries, Studio enquiries and versioned Studio quotes already exist.
- The active Studio quote portal supports secure token-based quote viewing and customer acceptance, decline or change requests.
- The public Archive still submits one creation enquiry at a time; this is not a multi-item order basket or paid checkout.
- The reviewed active Edge Function inventory contains no dedicated payment-gateway checkout creation or payment-webhook function.
- Reviewed RLS policies do not allow anonymous order creation; payment records are staff-managed. This is appropriate as a boundary, but a validated server-side checkout function is still required.
- Quote acceptance has not yet been verified as converting to exactly one order and invoice/payment journey.

### New architectural recommendation
- Keep the Archive POA (Price on Application) and use a request-basket → feasibility review → versioned quote → customer acceptance → confirmed order/invoice → secure payment checkout flow.
- Yoco Checkout API is the recommended first gateway candidate, subject to merchant verification and owner setup. Build server-side checkout initiation, signed webhook verification, replay protection, idempotency, refunds and reconciliation before live use.
- Reserve Career Guide as a separate future module with versioned API/event contracts and separate learner profile/consent boundaries. Do not embed career data in commerce customer/order records.
- Transfer lightweight Cosmo capabilities into Elaine's system: event-driven workflows, traceable quote/pricing decisions, provenance/licensing, audit history, role/approval controls, business intelligence, cost governance and evaluation tests. Keep Cosmo's central Memories/History Vaults, CC, CC-SIM, TIVA and global agent governance in Cosmo itself.
- Live payments remain blocked until merchant credentials, sandbox tests, webhook verification, RLS isolation, quote-to-order conversion, refund handling, business policies and backup/restore are tested.
