## Changes made during this audit
1. **Fixed public-intake validation ordering.** The handler previously required both a valid email address and a two-character name before checking the request type. This incorrectly blocked newsletter sign-ups with an optional blank name, unsubscribe requests that only carry a token, and the authenticated admin new-stock campaign action. Contact details are now required only for Studio enquiries, customer-care cases and reviews; the newsletter handler validates its own email and consent.
   - Source: `supabase/functions/public-intake/index.ts`
   - Deployed to Supabase as **public-intake v12**.
   - Verified the deployed function is ACTIVE and contains the new validation.
   - Full browser/API submission testing remains outstanding.
2. **Expanded the XML sitemap** to include the public Creation Archive, Privacy Policy and Terms pages as well as the homepage. The admin page remains excluded.
   - Source: `sitemap.xml`
3. **Added three missing foreign-key indexes** identified by Supabase's performance advisor:
   - `admin_push_subscriptions(user_id)`
   - `customer_new_arrival_campaigns(product_id)`
   - `studio_quotes(created_by)`
   - Applied as migration `add_missing_foreign_key_indexes`.
   - Verified all three foreign-key columns now have covering indexes.

## Security and performance findings
- **Security warning remains:** Supabase Auth leaked-password protection is disabled. Enable it in the Supabase Auth password-security settings. This requires a dashboard-level Auth configuration change and was not changed by this audit.
- Supabase performance advisor reports multiple permissive RLS policies on 11 tables. These are performance warnings, not proof of an access-control bypass; review policy overlap and consolidate only after validating the intended public/customer/staff access matrix.
- The advisor also reports 53 unused indexes. Do not mass-delete them: this is a relatively new project and low usage can make valid indexes appear unused. Reassess after real workloads.
- No claim is made that every RLS policy, Storage bucket or customer-data path has passed a full penetration/security test.

## Release recommendation
Keep the public site as a catalogue-and-enquiry experience for now. Do not enable live checkout or accept online payments until payment security, customer-data controls, legal/business details, backup/restore and end-to-end tests are complete.

The public site and admin code may be deployed, but this audit does not certify that the custom domain is currently reachable or that every GitHub Actions deployment/APK build triggered by recent commits has completed successfully.
